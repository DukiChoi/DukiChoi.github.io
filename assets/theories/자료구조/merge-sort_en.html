Merging compares the front values

Both runs are sorted, so the smaller front value is the next overall minimum. Merging takes time proportional to their combined lengths. There are O(log n) levels with O(n) merging work per level, for O(n log n) time even in the worst case.

When equal, the left value is chosen first (a[i] <= a[j]), preserving stability. Changing the comparison to < breaks this property.

Coding exercises: count inversions

When the next right-hand value is smaller, every remaining value in the left run is larger. Add mid − i + 1 to the inversion count at that step. The total is computed in O(n log n).
